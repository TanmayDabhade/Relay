## Design

**1. Backend — one new read-only command** (`src-tauri/src/commands.rs`, `lib.rs`)

The transcript text currently never reaches the frontend; `export_transcript` renders and writes in one step. I'll split out the rendering so copy and export can't drift:

- New pure fn `render_transcript_document(session, transcript) -> String` — the header + body concatenation that's currently inline at `commands.rs:504-507`. Pure, so it's unit-testable with no DB (matching the existing test style in that file, which has no DB harness).
- New command `get_transcript_markdown(db, session_id) -> Result<String, String>` — same lookup + `parser::render_markdown` as `export_transcript`, returns the document instead of a path.
- `export_transcript` refactored to call both, so its on-disk output stays byte-identical.
- Register the command in `lib.rs:79`'s handler list; add `getTranscriptMarkdown()` to `src/lib/tauri.ts`.

This is the one thing outside "session details," and it's unavoidable — the alternative (export-then-read-the-file-back) writes a stray Downloads file on every copy, which is the behavior you're removing.

**2. New shared `CopyButton`** (`src/views/CopyButton.tsx` + `.css`) — placed in `src/views/` since both consumers live there.

Props: `getText: () => string | Promise<string>`, `label`, `variant`. Internal state `idle → copying → copied → idle` (2s timeout, cleared on unmount), plus an `error` state. Copy is attempted via `navigator.clipboard.writeText`, falling back to a hidden-textarea + `document.execCommand("copy")` — **this fallback is not optional**: Tauri v2 serves macOS from a custom protocol that WKWebView doesn't reliably treat as a secure context, so `navigator.clipboard` can be `undefined` or reject at runtime. Status text gets `aria-live="polite"`.

**3. Transcript copy** (`SessionDetailModal.tsx:183-207`)

`<CopyButton variant="primary" label="Copy transcript" getText={() => getTranscriptMarkdown(session.id)} />` added at the head of the existing export row. "Export transcript" and its Saved-to / Reveal-in-Finder status line stay exactly as they are, now visually secondary.

**4. Diff copy** (`DiffModal.tsx`)

Pure fn `formatDiffForClipboard(data): string` — `data.lines.map(l => TAG_PREFIX[l.tag] + l.content).join("\n")`, with a trailing `[diff truncated — too large to show in full]` marker appended when `data.truncated`, so a pasted diff is never silently partial. Button renders in the meta row (`DiffModal.tsx:45-48`) only when `data` exists and `data.lines.length > 0`. Entirely client-side — the diff is already in the frontend.

**Testing** (TDD — Rust test written first)
